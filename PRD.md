# PRD — Nexora Store
Версия 1.0 · Черновик для согласования

## 1. Описание
Nexora Store — адаптивный интернет-магазин электроники и товаров для дома для аудитории Узбекистана. Функциональную основу изучаем по публичным сценариям MediaPark, а дизайн — по присланному референсу Nexora: navy/фиолетовые цвета, яркие акценты, крупные баннеры, Bento Grid, карточки товаров и плавные анимации. Создаём собственный бренд и реализацию, а не копируем исходный сайт.

Референсы: https://mediapark.uz/ · каталог: https://mediapark.uz/uz/category · способы оплаты: https://mediapark.uz/paymentmethods

## 2. Цели
- Дать покупателю удобный поиск, каталог, карточку товара, корзину и оформление заказа.
- Реализовать регистрацию, вход, личный кабинет, смену пароля, аватар и историю заказов.
- Дать администратору инструменты управления товарами, категориями, ценами, остатками, акциями и заказами.
- Подготовить API и архитектуру для будущих Telegram Mini App и Expo-приложения.
- Подготовить тестовую интеграцию YooKassa, не включая реальные платежи без отдельной проверки.

## 3. Роли
- Гость: каталог, поиск, товар, корзина.
- Покупатель: оформление заказа, профиль, адреса, аватар, история заказов.
- Администратор: товары, категории, остатки, заказы, промобаннеры.
- Менеджер поддержки — опционально, после MVP.

## 4. Состав MVP
Входит: главная с баннерами и подборками; каталог категорий; поиск, фильтры и сортировка; карточка товара; избранное; корзина; checkout; заказ и статусы; регистрация/вход по email и паролю; восстановление пароля; Google OAuth при настроенных ключах; кабинет; моковая аватарка и загрузка новой; адреса; история заказов; защищённая админка; адаптивность; состояния загрузки/ошибок/пустого результата; тесты; README и `.env.example`.

Тестовая YooKassa — отдельный этап и feature flag, выключенный по умолчанию. Google OAuth требует настроенных credentials. Не включать в MVP без отдельного решения: реальное кредитование, ERP/складские интеграции, бонусный кошелёк, push-уведомления, полноценный Telegram-бот и мобильное приложение.

## 5. Главные пользовательские сценарии
**Покупка:** главная → категория/поиск → фильтры → товар → корзина → контактные данные и доставка → подтверждение → номер заказа и статус.

**Кабинет:** регистрация или Google → профиль → аватар/пароль/адреса → история и детали заказов.

**Админ:** безопасный вход → редактирование товара/остатка → управление заказом и баннерами → изменения видны на сайте.

## 6. UX/UI
- Тёмно-синяя и фиолетовая основа, голубое свечение, коралловый акцент для основных CTA.
- Bento Grid для баннеров и подборок; единообразные карточки товаров.
- Анимации короткие и ненавязчивые; поддержать `prefers-reduced-motion`.
- На мобильных фильтры открываются в drawer, элементы управления достаточно крупные.
- Все экраны имеют loading, empty, error и success-состояния.
- Контраст, клавиатурная навигация, видимый focus и подписи полей обязательны.

## 7. Технологический подход
Если стек ещё не выбран: Next.js + TypeScript, React, PostgreSQL, Prisma или Drizzle (выбрать один), проверенная auth-библиотека, тесты unit/integration и Playwright. Motion использовать только при совместимости с текущим проектом.

**Сначала изучить существующий репозиторий и подключённые skills.** Не переписывать проект и не добавлять библиотеки, пока не проверены структура, `package.json` и инструкции skills.

## 8. Нефункциональные требования
- Серверная валидация, роли и права доступа; секреты только в env.
- Не хранить платёжные данные карты; не логировать пароли и токены.
- Суммы и остатки пересчитывать на сервере.
- Оптимизировать изображения и не блокировать интерфейс анимациями.
- SEO-метаданные и читаемые URL для товаров и категорий.
- Валюта UZS; подготовить локализацию RU/UZ, язык MVP согласовать отдельно.

## 9. Критерии успеха
- Покупатель проходит сценарий от поиска до заказа.
- Нельзя увидеть чужие заказы или вызвать admin API без роли.
- Цена заказа вычисляется на сервере.
- Работают мобильная и desktop-версии.
- Есть тесты критической логики и инструкция чистого запуска.

## 10. Открытые вопросы
Уточнить языки интерфейса, города доставки, стоимость и сроки доставки, правила отмены/возврата, гостевой checkout, хранилище изображений и условия применения YooKassa для конкретного бизнеса и региона. Наличие подключённых skills в локальной IDE разработчик должен подтвердить отдельно.
