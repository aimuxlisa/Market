# TASKS GUIDE — как выполнять задачи простым языком
Для начинающего разработчика. Главное правило: маленький работающий результат лучше, чем большая недоделанная реализация.

## 1. Словарь
- **Frontend:** видимая часть сайта — страницы, кнопки, формы.
- **Backend:** сервер, который проверяет запросы и выполняет правила магазина.
- **База данных:** место хранения пользователей, товаров и заказов.
- **API:** правила обмена данными между сайтом и сервером.
- **Компонент:** переиспользуемая часть интерфейса, например карточка товара.
- **CRUD:** создать, посмотреть, изменить, удалить.
- **OAuth:** вход через сторонний аккаунт, например Google.
- **Миграция:** контролируемое изменение структуры базы.
- **Seed:** набор тестовых записей.
- **Webhook:** серверное уведомление от внешнего сервиса.
- **Feature flag:** переключатель функции.
- **Адаптивность:** подстройка сайта под телефон, планшет и компьютер.
- **Bento Grid:** сетка из блоков разных размеров.
- **MVP:** первая полезная версия продукта.
- **PRD:** зачем делаем продукт и для кого.
- **SPEC:** точные правила работы функций.
- **TASKS:** список работ по порядку.
- **Definition of Done:** условия, при которых задача действительно готова.

## 2. Перед кодом
1. Открой репозиторий и прочитай README.
2. Проверь `package.json` и текущий стек.
3. Найди и прочитай инструкции подключённых skills в своей среде разработки.
4. Запусти проект до изменений и зафиксируй ошибки.
5. Прочитай задачу в `TASKS.md` и соответствующий раздел `SPEC.md`.
6. Проверь, нет ли уже готового компонента или функции.
7. Не переписывай проект и не меняй стек без причины.

## 3. Цикл одной задачи
1. Скажи своими словами, какой результат нужен.
2. Посмотри текущий код.
3. Составь план из 3–6 шагов.
4. Сделай минимальное изменение.
5. Запусти проект.
6. Проверь обычный сценарий и ошибочные случаи.
7. Запусти доступные lint/test/build-команды.
8. Убедись, что в diff нет секретов.
9. Сделай commit.
10. Отметь задачу выполненной только после критериев готовности.

## 4. Как выполнять ключевые задачи

### T0.1 — изучить проект
Зачем: не сломать существующий код. Посмотри файлы, команды запуска, зависимости и страницы. Запусти проект. Запиши исходные ошибки. Не удаляй файлы и не переустанавливай весь стек только потому, что другой кажется моднее.

### T1.4 — база данных
Зачем: данные должны сохраняться после перезапуска. Выбери БД/ORM с учётом текущей архитектуры, настрой подключение через env, создай модели и миграцию, добавь тестовый товар и проверь чтение/запись. Пароли и ключи не должны быть в коде.

### T2.3 — Bento Grid
Сначала сделай сетку без сложных эффектов. Используй дизайн-токены, крупный блок для главного баннера и меньшие блоки для категорий/подборок. Затем адаптируй сетку под телефон. Проверь, что текст читается, элементы не перекрываются, горизонтального скролла нет.

### T3.4 — поиск и фильтры
Начни с поиска по названию, затем добавь категорию и диапазон цены, после — сортировку. Сохраняй параметры в URL. Проверь пустой результат и некорректные значения. Скопированный URL должен воспроизводить те же фильтры.

### T4.5 — серверная проверка цены
Браузер нельзя считать доверенным. Клиент отправляет ID товаров и количество; сервер берёт актуальные цены и остатки из БД, считает сумму и создаёт заказ. Если товара не хватает, сервер возвращает понятную ошибку. Изменение цены в DevTools не должно влиять на итог.

### T5.5 — аватар
До загрузки показывай нейтральную моковую картинку или инициалы. После выбора файла показывай предварительный просмотр. Сервер проверяет тип, размер и содержимое. Если загрузка не удалась, сохрани старый аватар и покажи сообщение. Пользователь не может менять чужой профиль.

### T6.1 — роли
Задай роли `customer` и `admin`. Проверяй роль на сервере в каждом admin API. Скрыть кнопку в интерфейсе недостаточно. Первого администратора создавай защищённой процедурой. Проверь, что обычный пользователь получает отказ даже при прямом запросе к API.

### T7.3 — тестовая оплата
Прочитай официальную документацию провайдера и проверь, подходит ли он конкретному бизнесу, региону и валюте. Используй только тестовые ключи в env. Создавай платёж на сервере. Не считай возврат браузера доказательством оплаты. Проверяй серверное уведомление, сумму, валюту и ID заказа. Повторное уведомление не должно менять заказ повторно.

## 5. Пример запроса AI-помощнику
«Выполни задачу T3.4 из TASKS.md. Сначала изучи текущую структуру и подключённые skills. Не меняй стек без причины. Кратко объясни план, внеси минимальные изменения, перечисли файлы и команды проверки. Не отмечай задачу готовой, пока не выполнены критерии TASKS.md и SPEC.md. Если не хватает бизнес-решения, задай вопрос, не выдумывай его».

Для ошибки: «Вот ошибка и шаги её повторения: [вставить]. Найди причину, объясни простыми словами, исправь минимально и проверь соседние сценарии. Не скрывай проблему заглушкой».

## 6. Ручная проверка перед завершением

### Покупка
- [ ] Товар открывается из поиска и категории.
- [ ] Товар добавляется и удаляется из корзины.
- [ ] Количество не выходит за остаток.
- [ ] Сумма верная.
- [ ] Заказ сохраняется с верным составом и суммой.
- [ ] Серверная ошибка показана понятным текстом.

### Аккаунт
- [ ] Регистрация, вход и выход работают.
- [ ] Неверный пароль не открывает кабинет.
- [ ] Аватар можно заменить.
- [ ] Нельзя открыть чужой заказ, изменив ID в URL.

### Админка
- [ ] Обычный пользователь не может вызвать admin API.
- [ ] Товар можно создать и изменить.
- [ ] Некорректная цена/остаток отклоняются.
- [ ] Статусы заказа меняются по разрешённым правилам.

### Адаптивность
- [ ] Телефон 360–390 px.
- [ ] Планшет около 768 px.
- [ ] Desktop около 1440 px.
- [ ] Нет горизонтального скролла и обрезанных кнопок.
- [ ] Анимации учитывают `prefers-reduced-motion`.

## 7. Когда нужно спросить владельца
Не угадывай правила, связанные с деньгами, безопасностью или обязательствами: цена и сроки доставки, города, отмена и возврат, юридические тексты, хранение данных, язык сайта, допуск YooKassa в production.

## 8. Что сдавать
Ссылка на репозиторий, README с запуском, `.env.example` без секретов, список реализованных/отложенных функций, инструкция создания администратора, результаты проверок, staging-ссылка при наличии и список известных ограничений.
